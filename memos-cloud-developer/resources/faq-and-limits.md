# FAQ 与资源限制

## 资源限制

### API 调用限制

| API | 单次输入限制 | 单次输出限制 |
|-----|------------|------------|
| addMessage | 40,000 tokens | - |
| searchMemory | 40,000 tokens | 事实记忆 25 条、偏好 25 条、Tool 25 条、Skill 25 条 |
| Chat | 8,000 tokens | 事实记忆 25 条、偏好 25 条 |

### 速率限制

- 每分钟总 tokens：≤ 400,000
- 建议 QPS：≤ 50（非硬限制，高并发可能受平台容量影响）

### 文档上传限制

- 支持类型：PDF, DOCX, DOC, TXT, JSON, MD, XML
- 单文件：≤ 100 MB，≤ 500 页
- 单次上传：≤ 20 个文件
- Skill 单文件 (.md)：≤ 100KB
- Skill 包 (.zip)：≤ 20MB，解压后 ≤ 200 文件

### 配额说明

- 免费配额按**开发者账户**计算，同账户下所有项目共享
- 失败请求（鉴权失败、参数错误、超限等）不消耗配额
- 超过单次调用限制的请求返回对应错误码，不扣配额

## 常见问题

### MemOS 和标准 RAG 有什么区别？

| 维度 | RAG | MemOS |
|------|-----|-------|
| 结果形态 | 原始文本段落 | 精炼的记忆单元（更少 token） |
| 检索范围 | 全量语料扫描 | 分层调度，命中更快 |
| 个性化 | 无 | 自动提取用户偏好 |
| 进化能力 | 静态 | 通过反馈/对话动态更新 |

RAG 提供外部知识，MemOS 提供内部记忆。两者可以结合使用。

### MemOS Cloud 核心接口是什么？

- `addMessage`：写入原始信息，自动处理为记忆
- `searchMemory`：检索相关记忆

### 记忆会膨胀吗？

不会。MemOS 通过合并、压缩、归档机制管理记忆生命周期，低价值记忆降权，高价值记忆合并或固化。

### 会影响推理延迟吗？

不会。调度器异步运行，记忆检索通常 600ms 内返回。

### 支持私有化部署吗？

支持。

### 可以和已有 RAG/知识图谱结合吗？

可以。MemOS 记忆单元可以接入 RAG 的向量检索层，也可以和外部知识图谱协同。

### 如何评估使用 MemOS 的 ROI？

关键指标：
- Token 消耗降低（更高效）
- 输出相关性提升（更准确）
- 用户留存率提高（更理解用户）
- 知识固化率（长期沉淀多少信息）

### addMessage 后多久能检索到记忆？

- 异步模式：通常几秒到几十秒
- 同步模式：接口返回即可检索
- 多模态（文件/图片）：处理耗时较长，可通过 `get/status` 查询进度

## 错误排查

| 错误场景 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 401 Unauthorized | API Key 无效或过期 | 检查 Authorization header 格式：`Token YOUR_KEY` |
| 参数错误 | 缺少必要字段 | 确认 `user_id` 和 `conversation_id` 已提供 |
| 超限 | 单次 token 超过 40,000 | 拆分消息分批写入 |
| 检索无结果 | 记忆尚未处理完成 | 等待几秒后重试，或使用同步模式 |
| 文件处理失败 | 超过文件大小/页数限制 | 按限制要求调整后重试 |
